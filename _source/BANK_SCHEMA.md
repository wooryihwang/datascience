# 문제 은행 스키마 (public/data/bankN.js)

레슨 데이터(unitN.js)는 수정하지 않는다. 문제 은행은 별도 파일 `public/data/bank1.js` ~ `bank4.js`.

```js
window.DS_BANK = window.DS_BANK || {};
window.DS_BANK["1-1-1"] = [
  { step: 0, q: "문제", options: ["보기1", "보기2", "보기3", "보기4"], answer: 2, explain: "해설" },
  ...
];
window.DS_BANK["1-1-2"] = [ ... ];
```

## 규칙
- 레슨마다 **새 문제 25개**. 기존 unitN.js의 `test`(10개)·`steps[].check`(계단 수만큼)와 **겹치거나 거의 같은 문제 금지**.
- `step`: 그 문제가 다루는 계단 번호(0부터, 그 레슨의 steps.length - 1까지). 계단마다 **최소 4개** 이상 고르게 배정. 이 문제들은 ① 해당 계단의 확인문제로 무작위 출제되고 ② 마무리 시험(10문제 무작위)에도 출제된다. 그러므로 그 계단 설명(body/table/code/tip/remember)만 읽은 학생이 풀 수 있어야 한다. 이야기 속 인물·사건 문제는 금지.
- 4지선다, `answer`는 0~3 정답 인덱스. 정답 위치를 레슨 안에서 고르게(각 위치 5~8개).
- 선택지 앞에 ①② 같은 번호 금지. 해설에서 "③번은…"처럼 **번호로 선택지를 가리키지 말 것**(내용으로 설명).
- 문제 유형을 다양하게: 개념 정의, 예시 고르기, 옳은/옳지 않은 것, 짧은 계산(직접 검산), 코드 결과 해석, 상황 적용.
- 정답이 하나뿐이고 명확해야 함. "모두 옳다/모두 틀리다" 남용 금지. 오답도 그럴듯하게.
- 해요체. 해설은 1~2문장으로 왜 정답인지(필요하면 오답이 왜 틀렸는지).
- 문자열 따옴표 이스케이프 주의. 유효한 JS.
