# 글 줄이기 지침 — 계단 설명과 이야기를 PPT처럼

학생들이 글자가 너무 많아 읽기 힘들어해요. 레슨의 **계단 설명**과 **이야기(먼저 읽어 봐요)**를 발표 슬라이드처럼 핵심만 남겨 **반 이상** 줄여요. 프로젝트: `C:\Users\user\Documents\datascience-site`.

## 도구 (`_source/condense.js`)
- `node _source/condense.js stat public/<과목> <unit파일>` — 레슨별 현재 글자 수
- `node _source/condense.js dump public/<과목> <unit파일>` — 이야기, 계단마다 설명·표·팁·기억할 것, 그리고 **그 계단에서 나오는 문제와 정답**(확인문제 + 문제 은행)
- `node _source/condense.js apply public/<과목> <unit파일> <patch.json>` — 고친 내용 적용. 패치 형식:
```json
{ "1-1-1": {
    "story": { "paragraphs": ["...", "..."], "question": "🤔 ..." },
    "0": { "body": ["<p>...</p>", "<ul><li>...</li></ul>"], "table": null, "tip": "💡 ...", "remember": ["...", "..."] },
    "1": { "body": [...] }
} }
```
  적은 항목만 바뀌어요. `null`은 그 항목을 지워요. 계단 제목·코드·확인문제·시험·실습·용어는 **바꾸지 않아요**.
- 패치 파일은 프로젝트 밖(스크래치 폴더)에 만들어요. 크면 레슨 몇 개씩 나눠 여러 번 apply해도 돼요.

## 계단 설명 (body·table·tip·remember 합계)
- 목표: 레슨마다 계단 글자 수를 지금의 **45% 이하**로 (stat으로 확인).
- 모양: 첫 줄 `<p>` 한 문장(40자 안팎)으로 이 계단의 핵심을 말하고, 그 아래 `<ul><li>` 글머리 3~6개.
  - 항목 하나는 `<b>핵심어</b> — 짧은 설명` 한 줄(30자 안팎). 예시는 `<br>예) …`로 짧게.
  - 슬라이드처럼 명사형 끝맺음 가능(예: "데이터에서 패턴을 찾아 점점 개선"). 첫 줄 문장은 해요체.
  - 긴 문단 금지. 접속사·수식어·되풀이 설명을 빼요.
- 같은 내용을 글머리와 표로 두 번 쓰지 말아요. 표가 더 잘 정리되면 표를 남기고 글머리를 줄이고, 아니면 `"table": null`.
- tip은 한 문장 또는 지움. remember는 짧은 2개 이하.
- 코드(`code`)가 있는 계단은 코드는 그대로 두고, 코드 설명만 짧게.
- 허용 태그: p, b, strong, em, ul, ol, li, br, code, span, sub, sup.

## ⚠️ 꼭 지킬 것: 문제는 그대로 풀 수 있어야 해요
dump에 나오는 그 계단의 문제(확인문제 + 문제 은행)는 **줄인 계단 설명(body·table·tip·remember·code)만 읽고도 풀 수 있어야** 해요. 문제가 묻는 사람 이름, 연도, 숫자, 정의, 분류, 예시, 계산 방법은 짧게라도 꼭 남겨요. 다 쓴 뒤 문제를 하나씩 다시 보며 답의 근거가 남아 있는지 확인해요. 문제 자체는 고치지 않아요.

## 이야기 (story)
- 2~3문단, 합계 **250~350자 안팎**(지금의 40% 이하). 한 문단 2~3문장.
- 등장인물·화자·상황은 원래 이야기를 살리되, 레슨 핵심 개념에 대한 궁금증 **한 가지**로 모이게 단순하게. 답은 주지 않아요.
- 장면 묘사, 농담, 곁가지 사건은 빼요. 끝 질문(`question`)은 그대로 두거나 더 짧게.

## 끝내기 전에
1. `node _source/condense.js stat ...` — 레슨마다 계단·이야기 모두 반 이상 줄었는지
2. `node --check public/<과목>/data/<unit파일>.js`
3. `node _source/validate.js public/<과목>` — 오류 0
4. 내가 맡은 파일만 고쳐요. git 명령 금지.
